## 테스트·배포 순서

1. 팀 Firebase 관리 권한이 있는 PC에서, 최신 테스트 브랜치를 받는다. 저장소 루트의 브랜치와 프로젝트를 확인하고 변경된 API 함수만 배포한다.
   ```bash
   git log -1 --oneline
   npm ci --prefix functions
   npm --prefix functions run lint
   npx firebase-tools deploy --project solo-living-ai --only functions:api
   ```
2. 저장소 루트에서 `npm ci`, `npm run receipt:web` 실행. 앱에서 테스트 계정으로 로그인.
3. **소비 직접 입력**: 사용처와 당일 결제액을 저장. **서버 소비 기록**에 한 건 보이며 `users/{uid}/transactions` 아래 `source: manual`인지 확인.
4. **영수증 저장**: 우유와 사과주스를 넣고 우유만 식재료·냉장고 등록을 선택. 소비는 영수증 총액 한 건, 냉장고에는 우유 한 품목만 생기는지 확인.
5. **냉장고 식재료 추가**: 쌀 2kg·실온·기한 모름으로 저장. `users/{uid}/fridgeItems`에 2000g·기한 null로 표시되고 소비 기록은 늘지 않는지 확인.
6. 같은 계정으로 새로고침/재로그인, 다른 계정으로 재로그인. 같은 계정에만 실제 기록이 남아야 한다. 오늘 이외의 구매일은 소비 화면에서 해당 월을 선택한다.
7. 서버 기능 검증 후 Android/iOS 기기에서 권한·재시도·실제 화면을 확인한다. 월 합계, 재고 변경, AI 검증이 끝난 버전을 출시 후보로 사용한다.

데이터 계약: [RECEIPT_SHARED_DB.md](RECEIPT_SHARED_DB.md). 권한 오류를 우회하기 위해 Firestore 규칙을 공개로 바꾸지 않는다. API 테스트에는 테스트 계정을 사용한다.
