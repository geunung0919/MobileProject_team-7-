# 냉장고 최신본 팀 통합 안내

## 기준
feature/module3의 fridge-common-db-snack/가 이번 최신 전달본입니다.
module3-expo-router/는 이전 Expo Router 구현입니다. 두 폴더를 동시에 실행하지 않습니다.
main 또는 팀 통합 앱에는 아직 병합하지 않았습니다.

## 통합 위치와 책임
팀 앱의 mobile/src/features/fridge/에 필요한 module3/ 원본 변경을 이식하세요.
팀의 로그인, Session, 계정별 캐시와 기존 GET/PUT /api/v1/me/inventory 동기화를 보존해야 합니다.
이 폴더 AppProvider는 로컬 데모용이므로 팀 AppProvider를 통째로 덮어쓰면 안 됩니다.
src/와 integration/도 팀 UI 전체 대체용이 아니라 화면 연결 참고용입니다.

1. domain/의 식재료 식별·단위·검증·차감·되돌리기 계산과 테스트부터 비교합니다.
2. 화면 호출을 팀 상태 관리에 연결하고 등록/사용/폐기/조리를 같은 저장 경로로 묶습니다.
3. 영수증 화면은 확인된 분류·선택 여부·영수증/품목/소비 ID·수량·단위·날짜·보관 방법을 받아 registerReceiptItem 경로에 연결합니다.
4. 서버 어댑터에서 저장 필드와 단위를 확정합니다. 기존 서버의 piece/pack 및 fridge/freezer/room과 이 원본의 단위/보관 값은 명시적으로 변환해야 합니다.
5. 인증 UID, 원자적 저장, requestId와 요청 내용 검증, 서버 버전 충돌 처리를 구현한 뒤 통합 테스트합니다.

## DB 관련 완료/미완료
완료: 로컬 공통 명령, 영수증 출처, 영수증 품목 중복 방지, 일부 버전 검증, 관련 재고 변경 시 되돌리기 거부.
미완료: Firestore 연결, 서버 인증/트랜잭션, 계정별 데이터 이전, 영수증 UI 새 계약 연결, 서버 AI.
로컬 명령의 중복 방지는 운영 서버의 멱등성/동시성 보장을 대신하지 않습니다.
