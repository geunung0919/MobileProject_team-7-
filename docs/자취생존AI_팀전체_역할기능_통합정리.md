# 자취생존 AI — 팀 전체 역할 및 기능 정리

## 1. 프로젝트 한눈에 보기

### 프로젝트 목표
자취생이 혼자 생활하면서 겪는 **소비, 식재료, 생활 문제, 지역 정보**를 하나의 서비스에서 관리하고,
여러 데이터를 AI가 종합하여 **지금 사용자에게 필요한 행동을 알려주는 생활 관리 앱**을 만드는 것을 목표로 한다.

핵심 방향:

> **사용자가 일일이 관리하는 앱이 아니라, 생활 데이터를 최대한 자동으로 정리하고 AI가 필요한 행동을 먼저 알려주는 앱**

---

# 2. 전체 팀 구조

| 번호 | 담당 | 핵심 모듈 | 한 줄 역할 |
|---|---|---|---|
| 1 | 현동 | 중앙 코어 | 사용자와 각 기능의 데이터를 연결하고 전체 흐름을 관리 |
| 2 | 선웅 | 소비·예산 | 영수증/결제 데이터를 분석하여 지출과 예산을 관리 |
| 3 | 민혁 | 식재료·생필품 | 냉장고와 생활용품의 재고·소비주기를 관리하고 레시피를 추천 |
| 4 | 연규 | 프론트엔드 | 모든 기능을 사용자가 쉽게 사용할 수 있는 화면으로 구현 |
| 5 | 근형 | 생활정보·지역·비상 | 자취 생활에 필요한 지역 정보와 생활 문제 해결 정보를 제공 |
| 6 | 진혁 | AI 엔지니어링 | 각 모듈의 데이터를 종합하여 개인 맞춤형 AI 조언을 생성 |

# 3. 1번 — 현동
## 중앙 코어 / 데이터 파이프라인 & 온보딩 진단 엔진

### 핵심 역할
앱의 각 기능에서 발생하는 데이터를 연결하고 관리하는 **중앙 허브** 역할.

### 주요 기능

#### ① 초기 온보딩
처음 앱을 사용하는 사용자의 기본 생활 정보를 받는다.

예:
- 자취 기간
- 생활 패턴
- 월 생활비
- 요리 빈도
- 식비 비중
- 관심 기능

#### ② 생활 유형 진단
간단한 질문을 통해 사용자의 생활 유형을 분류한다.

예:
- 절약형
- 배달 중심형
- 요리형
- 계획형
- 관리 부족형

이 결과는 AI가 사용자에게 맞는 조언을 만드는 데 활용한다.

#### ③ 중앙 데이터 구조 설계
각 모듈에서 사용하는 데이터를 공통된 구조로 관리한다.

예:
```json
{
  "userId": "user001",
  "profile": {},
  "expenses": [],
  "inventory": [],
  "lifeInfo": [],
  "aiReport": {}
}
```

#### ④ 모듈 간 데이터 연결
2번 소비 데이터, 3번 재고 데이터, 5번 생활정보 등을 모아
6번 AI가 사용할 수 있도록 전달한다.

### 다른 모듈과의 연결
- 2번 → 소비 데이터
- 3번 → 재고 데이터
- 5번 → 생활/지역 데이터
- 6번 → 종합 분석
- 4번 → 최종 화면 표시

### 발표 포인트
> "각 기능을 따로 만드는 것이 아니라 하나의 사용자 데이터 구조로 연결하여 전체 서비스가 동작하도록 설계했습니다."

# 4. 2번 — 선웅
## 소비·결제 데이터 자동 파서 & 예산 엔진

### 핵심 역할
사용자가 돈을 어디에 얼마나 쓰는지 자동으로 정리하고,
예산을 기준으로 소비 상태를 분석한다.

### 주요 기능

#### ① 영수증 OCR
영수증 사진을 분석하여 정보를 추출한다.

예:
- 상호명
- 구매 상품
- 총 금액
- 구매 날짜

#### ② 결제 데이터 분석
문자나 결제 내역 등에서 소비 정보를 추출한다.

예:
> "OO마트 15,800원 결제"

→ 식비 / 장보기 / 15,800원으로 자동 분류

#### ③ 지출 자동 분류
- 식비
- 배달
- 교통
- 생활용품
- 쇼핑
- 기타

등으로 자동 분류한다.

#### ④ 예산 관리
월 예산과 현재 지출을 비교한다.

예:
> 이번 달 식비 예산: 300,000원  
> 현재 사용: 245,000원  
> 남은 예산: 55,000원

#### ⑤ 과소비 알림
평소 소비 패턴과 비교하여 이상 소비를 알려준다.

예:
> "이번 주 배달비가 평소보다 많이 증가했어요."

### 다른 모듈과의 연결
- 1번 → 사용자 예산/프로필
- 3번 → 구매한 식재료 정보
- 6번 → 소비 분석 및 절약 조언
- 4번 → 가계부/예산 화면

### 발표 포인트
> "사용자가 가계부에 직접 입력하는 과정을 줄이고, 영수증과 결제 데이터를 활용하여 소비 기록을 자동화했습니다."

# 5. 3번 — 민혁
## 식재료·생필품 생애주기 DB & AI 레시피 엔진

### 핵심 역할
집에 있는 식재료와 생필품을 관리하고,
언제 부족하거나 소비해야 하는지 판단할 수 있는 기반을 만든다.

### 주요 기능

#### ① 식재료 DB
주요 식재료의 정보를 관리한다.

예:
- 평균 유통/보관 기간
- 권장 보관 방법
- 평균 소비량
- 소비 주기

#### ② 냉장고 재고 관리
사용자가 등록한 식재료를 관리한다.

예:
- 계란 4개
- 우유 500ml
- 대파 1개
- 두부 1모

#### ③ 유통기한/소비 시기 알림
소비가 필요한 식재료를 알려준다.

예:
> "두부의 소비 시기가 가까워졌어요."

#### ④ 부족 물품 예측
사용자의 소비 패턴을 이용하여 부족할 가능성이 높은 물품을 예측한다.

예:
> "현재 소비 속도라면 우유가 약 2일 후 부족할 것으로 예상돼요."

#### ⑤ AI 레시피 추천
보유 식재료와 소비 시기가 가까운 식재료를 우선하여 레시피를 추천한다.

예:
> 계란 + 대파 + 햄  
> → 계란볶음밥 추천

### 다른 모듈과의 연결
- 2번 → 구매내역/구매 가격
- 1번 → 사용자 데이터
- 6번 → 맞춤형 식생활 분석
- 4번 → 냉장고/레시피 화면

### 발표 포인트
> "단순한 냉장고 목록이 아니라 식재료의 생애주기와 소비 패턴을 이용하여 음식물 낭비를 줄이는 것을 목표로 합니다."

# 6. 4번 — 연규
## 프론트엔드 / 통합 대시보드 & 사용자 경험

### 핵심 역할
1~6번의 기능을 실제 사용자가 쉽게 사용할 수 있도록 화면과 사용자 경험으로 구현한다.

### 주요 화면

#### ① 메인 대시보드
사용자의 현재 생활 상태를 한눈에 보여준다.

예:

```text
오늘의 생활 상태

💰 소비       🟡 주의
🥬 냉장고     🟢 양호
🏠 생활       🟢 양호

🤖 AI 오늘의 한마디
"이번 주 식비가 평소보다 조금 높아요."
```

#### ② 가계부 화면
- 최근 지출
- 카테고리별 소비
- 예산
- 소비 그래프
- 과소비 알림

#### ③ 냉장고 화면
- 보유 식재료
- 부족 식재료
- 소비 예정 식재료
- 추천 레시피

#### ④ 생활정보 화면
- 주변 시설
- 생활 문제 해결
- 비상 매뉴얼
- 생활 일정

#### ⑤ AI 화면
AI가 분석한 결과와 추천 행동을 보여준다.

#### ⑥ 알림/공유 화면
필요한 알림과 가족/지인과의 정보 공유 기능을 제공할 수 있다.

### 핵심 UX 방향

> "입력하는 앱"보다 "확인하는 앱"

예:
사진 촬영 → AI 분석 → 자동 등록 → 사용자 확인

### 다른 모듈과의 연결
1~6번의 결과를 최종적으로 사용자에게 보여주는 역할.

### 발표 포인트
> "복잡한 생활 데이터를 사용자가 한눈에 이해할 수 있도록 최소한의 조작으로 확인할 수 있는 UI를 구현합니다."

# 7. 5번 — 근형
## 라이프 DB / 위치·지역 정보 & 비상 상황 대처

### 핵심 역할
자취하면서 실제로 발생하는 **생활 문제와 지역 기반 정보**를 데이터베이스화하고
사용자가 필요한 순간 해결 방법을 찾을 수 있도록 한다.

### 주요 기능

#### ① 지역 생활시설 정보
사용자가 설정한 지역을 기준으로 필요한 시설 정보를 제공한다.

예:
- 24시간 약국
- 마트
- 세탁방
- 편의점
- 병원
- 생활 관련 시설

※ MVP에서는 실시간 GPS 대신 사용자가 직접 설정한 지역을 사용하는 방향을 고려한다.

#### ② 비상 상황 매뉴얼
자취 중 발생할 수 있는 상황에 대한 대응 방법을 제공한다.

예:
- 수도 누수
- 정전
- 가스 문제
- 보일러 문제
- 현관문 잠김
- 도어락 배터리 방전

#### ③ 생활 문제 검색
사용자가 상황을 입력하면 관련 정보를 찾아준다.

예:

> "현관문이 안 열려"

→ 도어락 배터리 확인  
→ 비상전원 여부 확인  
→ 관리실/집주인 연락  
→ 필요한 경우 전문 업체 안내

#### ④ 생활 루틴 DB
자취에 필요한 반복적인 생활 정보를 관리한다.

예:
- 청소
- 세탁
- 침구 세탁
- 필터 교체
- 쓰레기 배출
- 공과금 확인

#### ⑤ 연락처/도움 요청
사용자가 등록한 집주인, 관리실 등의 연락처를 빠르게 확인할 수 있도록 한다.

### 다른 모듈과의 연결
- 1번 → 사용자 지역/프로필
- 6번 → 상황에 맞는 AI 안내
- 4번 → 생활정보 화면
- 필요하면 공유 기능과 연계

### 발표 포인트
> "단순히 지출과 냉장고만 관리하는 것이 아니라, 실제 자취 생활에서 문제가 발생했을 때 해결할 수 있는 생활 지식까지 제공합니다."

# 8. 6번 — 진혁
## AI 자취 매니저 / LLM Prompt Pipeline

### 핵심 역할
1~5번에서 수집된 데이터를 종합하여
사용자에게 **개인 맞춤형 생활 조언과 행동 추천**을 제공한다.

### 주요 기능

#### ① 사용자 맞춤 AI Persona
사용자의 생활 유형과 데이터를 바탕으로 AI의 답변 방식을 개인화한다.

예:
- 절약이 필요한 사용자
- 요리를 자주 하는 사용자
- 생활 관리가 부족한 사용자

#### ② 데이터 종합 분석
AI에 다음 데이터를 전달한다.

- 소비 데이터
- 예산
- 식재료
- 구매 정보
- 생활 정보
- 사용자 생활 유형

#### ③ 일일 생활 리포트
예:

> 오늘의 생활 리포트  
>   
> 💰 식비가 평소보다 12% 높습니다.  
> 🥚 계란 소비량이 많아 구매가 필요합니다.  
> 🍳 냉장고 재료로 만들 수 있는 메뉴가 있습니다.  
>   
> 오늘의 추천 행동  
> **"배달 대신 냉장고 재료로 저녁을 만들어 보세요."**

#### ④ 상황별 AI 상담
사용자가 생활 문제를 질문하면 관련 DB와 데이터를 바탕으로 답변한다.

예:
> "이번 달 돈을 너무 많이 쓴 것 같아."

→ 소비 데이터 분석  
→ 주요 지출 원인 파악  
→ 구체적인 절약 방법 제안

#### ⑤ 행동 추천
단순히 정보를 알려주는 것이 아니라 실제 앱 기능과 연결한다.

예:
> "우유가 부족해요."

→ 구매 목록 추가

또는

> "두부를 빨리 소비하는 것이 좋아요."

→ 레시피 추천

### 다른 모듈과의 연결
**1~5번의 데이터를 받아 최종적인 판단과 추천을 생성하고,
4번 화면을 통해 사용자에게 전달한다.**

### 발표 포인트
> "ChatGPT를 단순한 챗봇으로 사용하는 것이 아니라, 앱 내부의 구조화된 생활 데이터를 기반으로 실제 행동을 추천하는 AI로 활용합니다."

# 10. 실제 사용 예시

## 예시 1 — 장보기

# 11. 데이터 입력 최소화 — Zero-Input 방향

이 프로젝트에서 중요한 UX 방향은
**사용자에게 모든 정보를 직접 입력하게 하지 않는 것**이다.

### 기존 방식

```text
사용자
 ↓
식재료 직접 입력
 ↓
가계부 직접 입력
 ↓
유통기한 직접 입력
 ↓
카테고리 직접 선택
```

### 목표 방식

```text
영수증 촬영
 ↓
AI/OCR 분석
 ↓
자동 정보 추출
 ↓
사용자 확인
 ↓
Firebase 저장
```

냉장고 역시:

```text
냉장고 사진
 ↓
AI가 식재료 분석
 ↓
사용자 확인
 ↓
재고 등록
```

핵심 원칙:

> **입력 노동을 확인 노동으로 바꾼다.**

# 12. 정보 공유 / 도움 기능

1인 가구의 특성상 사용자가 원할 경우
가족이나 지인에게 일부 생활정보를 공유할 수 있다.

### 공유 가능한 정보 예시

- 냉장고 상태
- 부족 식재료
- 구매 목록
- 생활 상태
- AI 알림
- 소비 요약

### 중요한 원칙

모든 정보를 자동으로 공개하는 것이 아니라

> **사용자가 공유 범위를 직접 선택한다.**

예:

```text
엄마와 공유

☑ 부족 식재료
☑ 구매 목록
☐ 가계부
☐ 상세 위치
☑ 생활 도움 요청
```

이 기능은 단순한 "부모의 자녀 감시"가 아니라

> **혼자 사는 사람과 도움을 줄 수 있는 사람을 연결하는 기능**

으로 정의한다.

# 13. 로그인 및 개인정보 보호 방향

### 로그인
Firebase Authentication + Google 로그인 등을 활용하는 방향을 고려한다.

### 위치정보
실시간 GPS를 반드시 사용하는 방식보다는
사용자가 직접 설정한 **지역 단위 정보**를 활용하는 방향을 우선 고려한다.

예:

> 아산시 / 배방읍

정확한 집 주소나 실시간 위치 수집은 MVP에서 최소화한다.

### 개인정보 원칙

- 필요한 정보만 수집
- 사용자 동의 기반 공유
- 민감한 정보 최소화
- API Key는 앱에 직접 노출하지 않음
- 서버/환경변수 등을 통해 API Key 관리

# 15. BM(수익 모델) 후보

## ① 광고
무료 앱을 유지하면서 생활과 관련성이 높은 광고를 제공한다.

예:
- 식재료
- 생필품
- 가구
- 세탁/청소
- 생활서비스

단순 배너 광고보다는 사용자의 상황과 연결된 광고를 고려한다.

## ② 커머스 제휴

```text
식재료 부족
 ↓
구매 필요 판단
 ↓
구매 목록 생성
 ↓
상품 추천
 ↓
구매
 ↓
제휴 수익
```

## ③ 장기적인 B2B 데이터 활용

개인정보를 판매하는 방식이 아니라,
적절한 동의와 익명화·집계 등을 전제로
1인 가구 소비 패턴에 대한 시장 인사이트를 제공하는 방향을 장기적으로 고려한다.

# 18. 최종 서비스 구조

이 프로젝트의 핵심은 6개의 기능을 따로 만드는 것이 아니다.

```text
① 중앙 코어
   ↓
② 소비 ───┐
           │
③ 식재료 ─┼→ ⑥ AI 분석 → ④ 사용자 화면
           │
⑤ 생활정보 ┘
```

각 모듈의 역할은 다음과 같다.

> **1번:** 데이터를 연결한다.  
> **2번:** 돈을 관리한다.  
> **3번:** 집에 있는 물건과 식재료를 관리한다.  
> **4번:** 모든 정보를 사용자에게 보여준다.  
> **5번:** 실제 자취 생활 문제를 해결할 정보를 제공한다.  
> **6번:** 모든 데이터를 이해하고 사용자에게 행동을 추천한다.
