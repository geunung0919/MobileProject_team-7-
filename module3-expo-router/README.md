# 냉장고 한 끼 · Module 3
React Native + JavaScript + Expo Router. 팀 저장소의 독립 실행 프로토타입입니다.

## 실행
이 폴더(package.json이 있는 module3-expo-router)에서 실행합니다.
```sh
npm ci
npm start
```
웹: `npm run web`. 테스트: `npm test`.
`scripts/setup.mjs`는 SDK 구성을 다시 만드는 도구입니다. 일반 실행에는 사용하지 않습니다.

## 구현 흐름
- 재고 등록/수정: 이름, 양수 수량(소수점 6자리), 단위, 구매일, 보관 방법, 날짜 유형, 기준 날짜, 선택 구매 금액.
- 추천: 예시 레시피 3개를 보유 재료와 임박 날짜로 정렬하는 **임시 추천**. 실제 AI 호출이나 비용 발생은 없습니다. 로딩, 빈 재고, 오류/재시도 화면을 제공합니다.
- 요리: 상세 → 요리 시작 → 실제 사용량 수정 → 차감 예정 수량/금액 확인 → 확인 후 차감 → 식사 기록.
- 실제 사용량 0은 해당 재료를 건너뜁니다. 최소 하나는 양수여야 하며, 기한 지난 배치는 요리 차감에서 제외합니다. 기름/소금 등 예시 레시피에 없는 기본 양념은 차감하지 않습니다.
- 재고 목록/수정 화면의 폐기하기 → 일부/전체 수량 및 선택 사유 → 남는 수량/금액 확인 → 확인 후 폐기. 폐기 기록도 저장합니다.
- 가장 최근 식사 차감 또는 폐기는 다음 재고 변경 전까지 되돌릴 수 있습니다. 수량·금액을 복원하고 해당 식사/폐기 기록을 제거합니다. 앱 재실행 후에도 가능합니다. 재고 추가/수정/삭제는 이전 되돌리기를 종료하며, 장보기 수정은 종료하지 않습니다.
- D-Day는 보관 참고 정보(추정)이며 실제 안전성을 보장하지 않습니다. 날짜 경과로 자동 폐기하지 않으며 보관 방법을 바꿔도 날짜를 자동 연장하지 않습니다.

## 구매 금액 규칙
`remainingCost`는 현재 수량에 해당하는 잔여 구매 금액(정수 원)입니다. 등록/수정 화면에서 직접 입력하며, 비워두면 null(미입력)입니다. 0원과 미입력은 구분합니다. 예전 재고에 금액을 추측해서 넣지 않습니다.
차감/폐기 금액 = 잔여 금액 × 차감 수량 / 현재 수량(원 단위 반올림). 전체 차감은 잔여 금액 전액을 사용해 반복 차감의 합계를 보존합니다. 재고 평가 금액만 변경하고 실제 가계부 결제 기록은 수정하지 않습니다. 수량을 직접 수정할 때는 금액도 사용자가 확인합니다.

## 저장 및 호환성
AsyncStorage의 기존 `module3.state.v1` 키를 유지합니다. 과거 inventory/meals/shopping 데이터는 그대로 사용하고 discards/undo/processedIds만 기본값을 채웁니다. 과거 재고를 수정할 때 구매일·보관 방법·날짜 유형은 입력해야 합니다.
변경은 순차적으로 저장하고 저장 성공 후에만 화면 상태를 바꿉니다. 저장 실패 시 완료로 이동하지 않습니다. 같은 거래 ID 재시도는 중복 차감하지 않으며, 취소한 거래 ID를 재사용하지 않습니다.
기기별 로컬 데이터이며 로그인/서버 동기화/실제 AI는 아직 연결하지 않았습니다.

## 주요 파일
- `src/app`: 탭/등록/상세/폐기 화면
- `src/components/InventoryForm.js`: 재고 입력
- `src/components/ReferenceNotice.js`: 공통 보관 참고일 안내
- `src/components/UndoCard.js`: 마지막 차감/폐기 취소
- `src/domain/inventoryFields.mjs`: 입력값 검증/저장 구조
- `src/domain/transactions.mjs`: 실제 사용량, 금액 비례 처리, 폐기, 되돌리기
- `src/state/persistentStore.mjs`: 저장 성공 후 상태 갱신, 순차 처리
- `src/state/AppProvider.js`: 데이터 공급/액션
- `src/services/recommendations.mjs`: 임시 추천 provider. 실제 API 연동 시 `recommendRecipes`의 provider를 교체합니다. 현재 상세 화면은 seed 카탈로그 기반이므로 실제 생성 레시피 도입 시 ID/상세 데이터 저장도 함께 연결해야 합니다.

### 사용 흐름
- 레시피 탭: 앱에 등록된 기존 예시 3개를 이름/재료로 검색. `계란`은 `달걀` 검색과 동일하게 취급합니다. 여러 검색어는 모두 일치해야 합니다.
- 10/15/30분 필터, 현재 재고로 가능한 요리만 표시, 조리시간순/추천순 정렬. 재고가 없어도 전체 검색은 됩니다.
- 레시피 상세: 기존 요리 시작 → 실제 사용량 → 확인 후 차감 흐름 유지. 부족 재료는 장보기로 추가합니다.
- 장보기: 직접 추가/수정/삭제, 구매 완료 체크, 쿠팡 상품 검색. 링크 이동은 주문·결제 또는 구매 완료를 자동 처리하지 않습니다.
- 같은 이름·단위의 미구매 항목을 반복 추가하면 큰 필요 수량을 유지합니다. 여러 끼 분량을 사고 싶으면 수량을 직접 수정합니다.
- 구매 완료 후 `구매한 품목 재고 등록`: 이름/수량/단위 미리 채움 → 구매일·날짜 유형·보관 방법 확인 → 재고 저장과 목록 연결을 한 번에 로컬 저장. 중복 등록 방지.
- 레시피 탭의 `매일 레시피 알림 설정`: 시각 입력 → 권한 허용 → 매일 일반 안내.
- 레시피 상세의 `이 레시피 알림 예약`: 다음 지정 시각에 한 번 알림. 오늘 시각이 지났으면 내일 예약. 같은 레시피 재예약 시 기존 예약 교체.
- 알림 탭 시 해당 레시피로 이동하며 목록에서 취소 가능. 웹은 예약 알림을 지원하지 않습니다.

### 범위
검색은 외부 레시피 검색 API나 실시간 AI 생성이 아닌 앱 내 카탈로그 검색입니다.
알림은 기기에 예약하는 로컬 알림이며 서버 푸시/백그라운드 재고 분석은 아닙니다.
매일 알림은 오래된 재고 스냅샷을 추천 사실처럼 보여주지 않도록 일반 안내로 보냅니다.
권한 및 OS 절전 설정에 따라 수신 시각이 달라질 수 있습니다. 실제 Android/iOS 기기에서 검증해야 합니다.
현재 앱 데이터는 AsyncStorage이며 Firebase/Firestore 연동을 새로 구현한 것은 아닙니다.
QR 설문은 `docs/QR_SURVEY_DESIGN.md`에 수집·임포트·동의·접근제어·버전 설계만 작성했습니다. 실제 설문 응답 수집이나 업로드는 하지 않습니다.
