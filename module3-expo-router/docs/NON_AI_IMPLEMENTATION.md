# AI 외 기능 업데이트 — 로컬 작업본

이 문서는 Expo Router 원본 프로젝트의 변경 범위입니다. Snack 한 파일 버전과 별개이며 Git 커밋/푸시는 하지 않았습니다. 새 의존성은 없습니다. Firestore·인증·Claude API는 연결하지 않았고 기존 기기 저장 방식(AsyncStorage)을 유지합니다.

## 포함 기능

- IV-01: 냉장/냉동/실온과 생필품 필터, 구매 묶음별 재고 및 보관 정보.
- IV-02: 개봉일과 보관 방법 변경, 변경 전/후 값과 시각 기록. 조리 외 실제 사용량 입력·초과 수량 방지·중복 차감 방지·되돌리기. 전체 변경 이력에서 삭제/소진한 재고도 추적.
- IV-04: 사용자 동의 후 D-3/D-1 오전 9시 기본 로컬 알림. 7/3/1/0일 및 시각 선택. 재고 수정/사용/폐기/삭제/복구 후 예약 비교·갱신. 다른 기능의 알림은 삭제하지 않음.
- IV-05: 해당 구매 묶음의 실제 사용 기록이 2건 이상, 1일 이상 간격으로 있으면 사용률로 잔량을 추정. 부족하면 수동 확인 주기 표시. '아직 남음' 확인 또는 잔량 수정 시 기준점 보정. 추정으로 실제 재고를 차감하지 않음.
- IV-06/07: 직접 입력한 날짜 수정과 알림 갱신, 표시 소비기한/참고일 구분. 열린 화면에서는 15초 이내 날짜/시간대 변화 감지, 앱 복귀 시 즉시 갱신.
- ME-01/06: 조리 도구, 시간, 예산, 체력, 제외 재료, 원팬/설거지 최소 조건 저장. 검색과 홈 추천에 적용. 직접 레시피 링크도 조건 검사.
- ME-04: 보유 재고 중복 구매 안내(계란/달걀 별칭 포함), 수동 예상 단가/비용, 미입력 가격 구분. 실제 지출에는 반영하지 않음.
- ME-05 일부: 낮은 체력에서는 15분 이내·설거지 최소 예시 메뉴만 제공. 간편식 가격 비교·포장·배달 공급자 연동은 없음.
- MO-02: 폐기 월별 금액/목록, 금액 미확인 건수, 폐기 취소 시 집계 제외.
- 공통: 보관 참고일과 포장 표시 소비기한의 설명 분리. 과거 상태는 기존 재고를 보존한 채 새 설정 기본값/배열 추가.

## 남은 범위 / 제한

- IV-03 검토된 보관 DB가 제공되지 않아 자동 소진일 추정은 구현하지 않음. 직접 입력으로 안내하며 임의의 보관 일수를 배정하지 않음.
- AI 연결/생성/대체 재료 가이드, 외부 레시피 API는 없음. 예시 레시피 4개(전자레인지 예시 추가)에 규칙 필터 적용.
- 예시 레시피에는 검증된 가격이 없음. 예산을 입력하면 가격을 모르는 메뉴는 제외되므로 결과가 없을 수 있음. 예산을 비우면 비용 조건 없이 검색 가능.
- 제외 재료 검사는 등록 재료명 기준이며 복합 재료의 상세 성분이나 알레르기 안전성까지 검증하지 않음.
- 생필품 예측은 같은 구매 묶음의 일반 사용량 기록만 사용하며, 소진 완료/폐기/미기록을 추정 소비 이벤트로 만들지 않음. 삭제된 사용 요청은 예측에서 제외.
- OS 예약은 앱 전체 60건을 보수적 한도로 사용(다른 기능의 예약 포함). 가까운 알림부터 예약하고 나머지는 미예약 건수로 안내. 앱 재실행/복귀 시 보충. 앱을 닫아 둔 동안 무제한 미래 예약 보충이나 시간대 변경 즉시 반영을 보장하지 않음.
- 지난 시각의 알림은 소급 발송하지 않음. 권한/절전/기기 재시작에 따른 실제 전달은 기기 확인 필요.
- 재고 저장과 OS 알림 저장은 서로 다른 시스템이며 원자적 처리가 아님. 예약 실패를 안내하고 설정 화면에서 재시도 가능.
- 되돌리기는 다음 재고 변경 전 최근 1건만 지원. 설정 변경은 재고 변경으로 취급하지 않음.
- Firestore/서버 권한/멀티기기 동기화/구매 거래 원자적 저장은 이 작업 범위에 없음.

## 실행과 확인

프로젝트 루트에서 `npm ci`, `npm test`, `npx expo start`를 실행합니다. `package.json`의 Expo SDK 버전에 맞는 Expo Go 또는 개발 빌드가 필요합니다.

1. 재고에 식재료와 생필품 각각 등록하고 장소/분류 필터 확인.
2. 구매일·개봉일·보관 방법 수정 후 전체 변경 이력 확인.
3. 생필품 일부 사용 → 잔량·금액 확인 → 되돌리기. 전량 사용해도 전체 변경 이력에는 기록이 남아야 함.
4. 레시피 조건에서 전자레인지만 선택 → 전자레인지 예시만 노출. 달걀 제외 시 해당 요리는 사라져야 함.
5. 레시피 예산 입력 → 가격 미확인 후보가 제외됨을 확인. 예산 비우기 후 다시 검색.
6. 장보기에서 이미 있는 품목 입력 → 보유 경고 확인. 예상 단가 입력 → 미구매 합계 및 미입력 건수 확인.
7. 일부 폐기 → 식사 기록 화면의 월별 폐기 비용 확인 → 되돌리기 후 합계에서 제외.
8. 휴대폰에서 임박 알림 활성화, 가까운 미래 시각 설정. 날짜 수정/품목 삭제 후 이전 예약이 취소되는지 확인. 권한 거절/회수 후 안내 확인.
9. 자정/시간대 변경 및 앱 백그라운드 복귀 시 D-Day 확인.

## 검증

- 기존 및 추가 도메인 테스트: 사용/취소/금액, 필터, 추정 보정, 알림 중복/변경/삭제/실패/한도, 월별 폐기 집계.
- Expo Web와 Android export 번들 확인.
- 실제 기기 알림 전달과 전체 화면 수동 조작 검수는 미실시.
- 커밋/스테이징/푸시하지 않았음. 업로드 전 팀원의 최신 변경과 비교할 것.
